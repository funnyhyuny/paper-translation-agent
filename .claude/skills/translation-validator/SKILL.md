# translation-validator

병렬 번역의 누락·환각·구조 손상을 규칙 기반으로 탐지한다. LLM 호출 없음, 결정론적 결과.

## 언제 사용

- 워크플로우 [5] 완료 직후: 각 워커 결과의 1차 검증.
- 워크플로우 [6] 자기검증 단계: 메인이 통합 검증 시 재호출.

## 제공 스크립트

| 스크립트 | 호출 |
|---------|------|
| `scripts/validate.py` | `python validate.py <sections_dir> <sections_kr_dir>` |

## 검증 항목

1. **완료 마커**: `sec_N_kr.md` 마지막 비공백 줄이 정확히 `<!-- DONE -->`인지.
2. **이미지 개수 매칭**: 원문 `![](...)` 개수 == 번역 `![](...)` 개수.
3. **수식 개수 매칭**:
   - 인라인 `$...$` (단, `$$` 블록 내부 제외)
   - 블록 `$$...$$`
   - 두 종류 각각 원문과 번역에서 개수가 같아야 함.
4. **길이 비율**: `len(번역 텍스트) / len(원문 텍스트)`가 0.6–1.2 범위 (수식·이미지·메타 주석 제외).
   - 범위 외면 누락 또는 환각 의심.
5. **마크다운 문법 유효성**:
   - 표 행의 파이프(`|`) 개수가 헤더와 동일한지
   - 코드블록(```) 짝수 개
   - 링크/이미지 괄호 `[](...)` 짝 맞음

## 출력 형식

stdout에 JSON 한 줄(각 섹션 결과):

```json
{
  "sec_0": {"ok": true},
  "sec_1": {"ok": false, "errors": ["image count mismatch: src=3 kr=2", "length ratio 0.42 out of [0.6, 1.2]"]},
  "summary": {"total": 5, "passed": 4, "failed": ["sec_1"]}
}
```

종료 코드:
- `0`: 모든 섹션 통과
- `1`: 일부 실패 (`failed` 배열 참조)
- `2`: 사용법 오류 등 시스템 에러

## 메타 처리

- `meta.translate == false` 섹션 (References 등)은 검증 대상에서 제외.
- 메타 주석은 길이 계산에서 제거 후 비교.
